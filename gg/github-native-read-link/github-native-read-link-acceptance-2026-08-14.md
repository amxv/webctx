# GitHub-native `read-link` acceptance matrix — 2026-08-14

This is a current-state verification matrix generated from the authoritative implementation-plan acceptance criteria. It does **not** treat historical progress-ledger claims as proof. All rows are PASS against current deterministic coverage plus the live evidence described below.

## Live authenticated/anonymous evidence added in the follow-up

- `.env.local` is ignored by Git and its `GH_TOKEN` is never printed or staged. The fine-grained token is valid: REST user lookup succeeds; authenticated capacity observed was 5,000 core/hour, 30 Search/minute, and 5,000 GraphQL/hour.
- Public `amxv/webctx` root/blob/tree/Issue/PR/PR-files/check/commit/compare/history/release/activity/deployment reads succeeded both with explicit-empty token variables and with the token configured.
- Blame is provider-truthful: anonymous read fails early with auth guidance; authenticated GraphQL blame succeeds.
- A current `vercel/next.js` Discussion is provider-truthful: anonymous read fails early with auth guidance; authenticated read returns the full paginated conversation.
- A current `cli/cli` inline review thread is readable anonymously via REST; authenticated output additionally exposes GitHub-truthful `resolved`, `outdated`, and resolver identity from GraphQL.
- A current `amxv/webctx` Actions run is public; its exact job-log URL returns an anonymous 403 but succeeds authenticated with the selected job's substantive log.
- `.env.local` loading is live-proven by an authenticated job-log read with both token variables removed from the process environment. `GITHUB_TOKEN` fallback also succeeds, and `GH_TOKEN` wins over a deliberately invalid `GITHUB_TOKEN`.
- Public Gist, User/Organization profile, and Search outputs succeeded both anonymously and with this repo-scoped fine-grained token.
- GitHub Packages exposed a real provider permission boundary: no token returns 401/auth-required; this fine-grained repository token returns 403/insufficient permission for the tested organization package endpoint.
- Current Projects v2 REST behavior is live-proven with public `github` Project 12106: forced-anonymous and fine-grained-token reads both succeed with byte-identical output, bounded to 50 returned items with `more_items_available: true`; the narrow token path reaches the same result through the public-GET anonymous retry.
- Current GitHub social-list provider behavior is recorded rather than assumed: after the anonymous quota reset, the API returned 401/auth-required for `amxv/webctx` subscribers and stargazers, while the supplied fine-grained token returned 403/insufficient permission. webctx distinguishes those states.
- Repository contributor statistics showed provider-state truth: anonymous request returned HTTP 202/computing; an authenticated fresh request returned GitHub's computed/cached data.
- Anonymous core capacity was deliberately exhausted during the matrix, and subsequent reads returned native rate-limit/reset guidance instead of Firecrawl fallback.
- The other live provider keys were exercised too: federated `webctx search` completed, generic Firecrawl `read-link https://example.com` returned `# Example Domain`, and `map-site https://example.com` returned 16 URLs, re-proving the non-GitHub provider paths after the GitHub auth changes.
