## Post-acceptance independent-review closure

The follow-up review deliberately challenged provider work and navigation rather than accepting bounded character counts as sufficient proof. It found and closed these gaps:

- **Pageable-list recoverability:** pageable Issues, PRs, branches, tags, releases, workflows/runs, Search, profile tabs, Packages, activity/deployments, and commit history now request a small stable provider page (`8`) and render every returned row. `Next`/`Previous` therefore cannot skip a locally omitted tail. Live Next.js PR pages 1+2 and `cli/cli` Issue-search pages 1+2 exactly matched GitHub's corresponding `per_page=8` result IDs.
- **Bounded authenticated PR enrichment:** PR-root review-thread state enrichment performs one bounded GraphQL page. Full GraphQL pagination remains available only to exact thread selection where the selected semantic object can require it.
- **PR comment discoverability:** ordinary PR comments have a dedicated index lane separate from timeline/state events, preventing force-push/review-request history from crowding every `#issuecomment-*` selector out of the root. Live `cli/cli#13250` now exposes all three returned ordinary-comment selectors.
- **Workflow navigation:** workflow indexes link to native `/actions/workflows/<file-or-id>` views; GitHub's source-blob URL is secondary metadata only when a real workflow path exists. The previously broken pathless Next.js workflow now resolves natively via workflow ID.
- **Release-note truthfulness:** truncated releases label the repeated root URL as the canonical GitHub browser page containing the complete notes; they no longer claim that feeding the same bounded `read-link` URL back will produce a separate “full release notes” representation.

Post-review validation passed the full Go suite, race detector, vet, npm shim checks, native build, Astro check/build, npm pack dry-run, and diff hygiene. Public live smoke reconfirmed the affected paths without recording credentials or private payloads.
